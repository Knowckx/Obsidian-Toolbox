## Clean Paste

状态：核心流程已实现；HTML 清理仍为占位；尚未完成 Obsidian 内的完整手工测试。

- 功能 ID：`clean-paste`
- 命令 ID：`clean-paste`
- 命令名称：`Clean paste`
- 默认快捷键：无
- 普通 `Mod+V`：不监听、不拦截，保持 Obsidian 原行为

处理流程：

```text
命令面板 / 用户自定义快捷键
→ navigator.clipboard.read()
→ 优先读取 text/html
→ cleanHtml()
→ Obsidian htmlToMarkdown()
→ cleanMarkdown()
→ editor.replaceSelection()
```

降级与异常处理：

- 剪贴板不支持 `read()` 时使用 `readText()`。
- 没有 HTML 时回退到 `text/plain`。
- 没有可粘贴内容时显示 Notice。
- 剪贴板权限或读取失败时显示 Notice。
- 按已确认决策，不检查异步读取期间是否切换了编辑器。

### Markdown 清理

状态：已实现并通过临时边界测试。

当前规则：

- 将 `CRLF` 和 `CR` 统一为 `LF`。
- 删除内容开头和结尾的空白行。
- 将代码块外连续空白行压缩为一个空白行。
- 识别反引号和 `~~~` fenced code block。
- 保留 fenced code block 内部的空行和内容。
- 不修改 Markdown 硬换行、列表、表格和引用结构。

已验证用例：

- 换行符归一化。
- 普通空行及空格、Tab 空白行压缩。
- 反引号 fenced code block 内容保持不变。
- `~~~` fenced code block 内容保持不变。
- Markdown 硬换行保持不变。
- 列表、表格和引用保持不变。
- 空字符串及纯空白输入。

## Markdown Table Transpose

状态：已实现，已在源码模式和实时预览模式中验证。

- 功能 ID：`transpose-markdown-table`
- 命令 ID：`transpose-markdown-table`
- 命令名称：`Transpose Markdown table`
- 默认快捷键：无
- 触发条件：光标真正位于 Markdown 表格内部

处理流程：

```text
执行命令
→ 根据光标位置定位完整表格源码范围
→ editor.setSelection() 选中表格
→ 删除 Markdown 分隔行
→ 将全部单元格作为矩阵转置
→ 根据转置后的列数重新生成分隔行
→ editor.replaceSelection() 原地替换
```

解析与输出规则：

- Markdown 分隔行不作为数据参与转置。
- 未转义的 `|` 作为列分隔符，`\|` 保留为单元格内容。
- 不赋予表头或第一列额外业务语义。
- 数据行缺少单元格时使用空单元格补齐。
- 原表的列对齐信息无法无歧义映射，输出统一使用 `---`。
- 找不到合法表格时显示 Notice，并保持文档不变。

已验证用例：

- 标准矩形表格整体转置。
- 转义 pipe 保留为单元格内容。
- 反引号内未转义 pipe 仍作为列分隔符。
- 不规则数据行补空单元格。
- CRLF 和尾随换行保持。
- 非法分隔行拒绝处理。
- 光标位于表头、分隔行或数据行时可定位表格。
- 光标位于表格相邻的普通文本行时拒绝处理。
